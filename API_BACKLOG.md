# API Backlog

Every UI-triggered operation on this platform that has no working backend behind it, ordered by
execution priority. Generated from a per-domain audit of all twelve feature areas, cross-checked
against `supabase/migrations/` and the fat service layer.

**This file is documentation. Nothing in it has been implemented** — Phase 5 of the task that
produced it was explicitly documentation-only.

## The headline finding

The platform has **119 API route files** under `apps/web/routes/api/`, so at a glance the backend
looks largely present. It is not. Counting real Supabase calls (`getUserClient`,
`getServiceClient`, `.from(`) across the twenty fat services:

| Fat service | Supabase calls | Reality |
| :--- | ---: | :--- |
| `AuthBackendService` | 15 | Real GoTrue path, behind `AUTH_BACKEND_LIVE` |
| `UserBackendService` | 5 | Real account read, behind the same gate |
| `ContextBackendService` | 2 | Real context switch |
| **The other 17 services** | **0** | **No database path exists at all** |

Those seventeen services follow one shape: test the gate, return fixtures when it is off, then
return *the same fixtures* when it is on. `CatalogueBackendService.list` is the clearest example —
both branches call `listListings(params)`. So **flipping `EXPLORE_BACKEND_LIVE`,
`PROJECTS_BACKEND_LIVE`, `FINANCE_BACKEND_LIVE` and the rest changes nothing today.** A reader of
`.env.example` alone would not learn that, which is why it is stated here first.

## How to read the Status column

| Status | Meaning | Work required |
| :--- | :--- | :--- |
| **No route** | The UI calls a path with no matching file under `apps/web/routes/api/` | Thin route + fat method + schema |
| **Inert handler** | A rendered, focusable control whose handler reaches nothing — it writes a signal nobody reads, or its body is empty | Wire the control, then the backend |
| Stub only | Thin route and fat service both exist; the fat service only ever returns fixtures or mutates an in-process store | Implement the live branch |
| Gated off (built) | The live path **is** implemented and sits behind an env flag | Flip the flag and verify — not a build |

An **Inert handler** is the most dangerous row type and the reason the audit looked for it
specifically: it is invisible to a type-checker and to a source-reading review, because the code
compiles and the control renders. This codebase has shipped that defect before (root `CLAUDE.md`
§3, gate 11).
