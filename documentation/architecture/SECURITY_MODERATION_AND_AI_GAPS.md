### 1.1 Commercial reading

E1 and E2 are not abstract. Disintermediation is the single largest revenue risk of a managed
marketplace: the 5% stage-completion fee (`finance-model.md`) and escrow TVL both disappear the
moment a client and a freelancer move off-platform. The Tier 2 trigger is the one control the spec
calls "the floor" (PS:982-983), and today the **client** — the party with the most to save — can
lift it with one `PATCH` (E2), while either party can smuggle details past it by editing (E1).
Upwork and Fiverr both treat this as a fraud signal, not a messaging feature. E3 attacks the other
half of the pitch: a trust-first escrow product whose own inbox can carry a forged "payout failed"
phishing notice is a reputational incident, not a bug.

### 2.3 Tier 1 — the contract to build

- **Where.** One pure module, `packages/types/comms/pii-detect.ts` (types package, so the composer
  can run the same function advisorily), called by **both** send doors before the insert:
  `MessagingBackendService.sendMessage` and `ProjectBackendService.sendMessage`, plus
  `comms.send_request_message`'s caller and every L7 surface's write service.
- **Pipeline.** NFKC → strip `\p{Cf}` (zero-width) → fold confusables (a vendored Unicode
  `confusables.txt` subset; Latin, Cyrillic, Greek and full-width digits are enough to start) →
  collapse `at`/`dot` spellings → extract URLs and bare domains (`linkify-it`, registrable domain
  via `tldts`) → match the payment/messaging host list **read from the same SQL source as Tier 2** →
  Luhn on 13-19 digit runs → mod-97 on IBAN-shaped runs.
- **Output.** `{ refused: boolean, categories: PiiCategory[] }`. A refusal is `422` with the
  category list; the composer shows it inline. Refusals are counted, not stored (#147 flag (b) still
  needs a ruling on refusal logging; recommendation: count per user per day in `ops.log_entries`,
  never the text).
- **Contract test.** One fixture corpus (`packages/types/comms/pii.fixtures.ts`) run against
  `pii-detect.ts`, `maskPii`, and — through a probe — `comms.mask_pii`, asserting Tier 2 masks every
  case Tier 1 refuses.

**Ruled:** T4 — refusals are logged as a count per user per day, never the text (#147 (b)); T2.1
places Tier 1 in-process on the send path. **Status:** Open → T·P1d. COMMS MS2 builds the single

### 2.5 Public copy (§1.B) must be enforced in the database

The design puts the public-copy refusal in the service write doors (SA:1161-1166, PS:1010-1013), but
PS:982-983 makes the database the floor, and the doors are not the only writers:
`catalogue.listings` and `catalogue.products` grant `INSERT` / `UPDATE` to clients (G2520:722), and
`marketplace.service_blueprints` and `projects.projects` carry owner `UPDATE` policies
(`00002018:35-37`, P2011:193). The refusal must therefore be a `BEFORE INSERT OR UPDATE` trigger
that `RAISE`s with a field-named `SQLSTATE` the services translate to `422` — the pattern the
feedback board already uses (`00001320:402-408`). `org.users_public` has no client write policy
(TR1895:59-62), so `org.save_profile` alone is sufficient there. This is a doc contradiction to
record (#340 (c)).

**Ruled:** T2 (a) ⭐ — `BEFORE INSERT/UPDATE` triggers refuse at the database floor; services
translate to 422. **Status:** Open → T·P2a (the leakage half); toxicity and hate → T·SN4
(Sightengine). TRUST §0.4 records a new, unlogged contradiction here: PS §Messaging 1.C screens
public text before publication, but a hosted classifier cannot run in a trigger while clients hold
direct write grants on public copy.

### 2.6 Strategic call — the pre-engagement window

PS:954 starts the protected phase "from the initial proposal". The code is narrower still (L4), and
a service inquiry or a profile DM before any proposal is unprotected by design. That window is
precisely where Fiverr and Upwork concentrate their filtering, because it is where a buyer who has
found talent through the marketplace decides whether to pay through it. **Recommendation:** extend
Tier 2 to any thread whose first message was sent through a marketplace surface (service inquiry,
listing, explore card, proposal) until a first escrow funds or 30 days pass, and keep ordinary
profile-to-profile DMs between connected users unprotected. It needs a ruling because it changes
user-visible behaviour (#340 (b)).

**Ruled:** T1 = (b) ⭐ — adopt this section, plus a cooling-off window after an engagement ends.
**Status:** Open → T·P2b (⏳ COMMS MS1, MS2, P·WP4). Still unruled (TRUST §0.4): the cooling-off
length (recommended 30 days, its own dial) and a cold DM opened from a profile reached through
Explore (recommended: protected).

### 3.4 Strategic flag — known illegal material in the private zone

EPI §2 places the node in Zone D (private link only, one bearer or mTLS identity, no payload kept)
and EPI §6.1 sizes it at 4 vCPU / 8 GB. Bringing it up before the database holes close would buy
little: every analyzer sits **behind** a door the attacker can walk around today.
