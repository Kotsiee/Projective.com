Method: source read + **measured in-browser** (dev server `web-cards`, port 8173, light and dark).

## P0 — THE HEADLINE: `explore.css` never reaches `/explore`

`apps/web/features/explore/components/ExploreScreen.tsx:2-3` imports both explore sheets on adjacent
lines. Only one is delivered.

Measured, cold server, first hit, after full hydration (2.5s settle):

| Route | `<link>` emitted | `.ex-card` rule in CSSOM | Rendered `.ex-card--service` |
|---|---|---|---|
| `/explore` | `explore-results.css` only | **absent** | `display:block`, bg `rgba(0,0,0,0)`, border `0px`, radius `0px` |
| `/explore?category=services` | `explore-results.css` only | **absent** | same |
| `/@northwind` | none (island-injected) | present | correct |
| `/view/sv-brand-identity-sprint` | none (island-injected) | present, bg `rgb(29,32,33)` | correct |
| `/` | `landing.css` | n/a | correct |

**Root cause.** `ExploreScreen.tsx` is a server component, so its CSS imports depend on the SSR CSS
walk. `explore-results.css` survives because `profile.css:11` also `@import`s it; `explore.css`
survives on `/@handle` and `/view` for the same reason (`profile.css:10`). `/explore` has no such
carrier, and `CardStyleAnchor.island.tsx` — the island created precisely to anchor shared card CSS —
imports the `@projective/ui` sheets, not `explore.css`.

**Confirmed in the production build, not just dev.** `apps/web/_fresh/server/.vite/manifest.json`
(built 2026-07-30) contains `assets/explore-results-D2Mujly7.css` and **zero** `explore*.css` asset
for `explore.css` — it exists only inlined into the profile bundle.

Every finding below about `.ex-card` describes CSS that is currently dead on the surface it was
written for. **This is a one-line fix** (add `import "../styles/explore.css"` to
`CardStyleAnchor.island.tsx`) and it must land before any card redesign, or the redesign cannot be
seen.

## 2. THE DUPLICATION QUESTION — verdict: **marketing is a stale fork. Retire it.**

Band-by-band, marketing vs explore, same concept:

| Band | `.lp-service` | `.ex-card--service` | Verdict |
|---|---|---|---|
| Media ratio | 4:3 | 16:10 | explore's is the later, deliberate choice (§ lean pass) |
| Media overlay | category `Tag` | one glass engagement-type chip | explore replaced the category tag on purpose |
| Attribution | `provider` — **plain text, no avatar, no link** | `OwnerBadge` — avatar + linked `@handle` | explore is strictly richer |
| Rating | **absent** | `RatingStars compact` | explore only |
| Foot | price + delivery | price + delivery | identical |
| Hover | lift −6px + zoom 1.05 | lift −4px + zoom 1.045 | arbitrary divergence |
| Reduced motion | **none** | present | explore only |

| Band | `.lp-profile` | `.ex-card--banner` | Verdict |
|---|---|---|---|
| Cover | 8.5rem | 9rem | arbitrary |
| Identity | Avatar + name + handle | same + `VerifiedBadge` | explore only |
| Body | craft + **skills `Tag` row** | craft + `RatingTracks` + languages | different content, same slot |
| Rating | `Icon star` + number, `color: --primary` | dual-track `RatingTracks` | explore models the real dual-track reputation |
| Foot | rating + rate | delivered + members | — |

**The decisive evidence that one is a fork of the other:** both carry the *same fossil*. Marketing
sets `--lp-span` (`ProductCard.tsx:15`) and explore sets `.ex-card--span{n}`
(`ProductCard.tsx:26`) — **neither is consumed by any CSS rule anywhere**. Both JSDocs claim "`span`
drives its column weight". Both are lying, identically. A dead prop does not evolve into two
codebases independently.

Marketing is also strictly behind on defects already fixed in explore: no `prefers-reduced-motion`
branch (`landing.css:576`, `697`, `866`), and the glass-over-photo chip
(`landing.css:870-882`) that explore diagnosed and replaced with a solid surface
(`explore.css:21-38`).

**Recommendation — unify, one direction only.** Make `.ex-card` canonical. Marketing's four cards
become thin adapters that map `ServiceShowcase`/`ProductShowcase`/`ProfileShowcase`/`ProjectShowcase`
onto `ExploreItem`-shaped props and render the explore components. Delete `.lp-service*`,
`.lp-product*`, `.lp-profile*`, `.lp-project*` from `landing.css` (≈220 lines).

**Not a blind merge — one real difference is legitimate and must be preserved.** `.lp-project` is a
*card*; `.ex-projrow` is a *list row*. The landing page sells open pipelines as hero objects and
legitimately needs the boxed treatment with the `ProgressBar`; the search feed needs a scannable
list. Keep `.lp-project` as the one marketing-only card, or add an `.ex-card--project` variant. Do
not convert `.ex-projrow` to a card (explicit constraint) and do not flatten the landing grid to
rows.

**How the CSS arrives on the landing page.** `landing.css` is delivered by the `/` route's page
graph (verified: it is the only `<link>` on `/`). Add `@import "../../explore/styles/explore.css";`
at the top of `landing.css` — the exact mechanism `profile.css:10` already uses to deliver the same
sheet to `/@handle`, verified working in the build manifest (explore.css is inlined into the profile
bundle). This is proven, not theoretical. Verify after the change that `.ex-card` is in the CSSOM
on `/`.

## 3. Structural consistency within `.ex-card` — measured

Measured on `/view/sv-brand-identity-sprint` (the surface where the CSS actually lands), dark theme,
desktop.

| | `--service` | `--product` | `--article-grid` | `--article-list` | `--banner` | `--talent` |
|---|---|---|---|---|---|---|
| Body padding | 24px | 24px | 24px | 24px | `0 24 24` | `0 24 24` |
| Body row-gap | 12px | 12px | 12px | 12px | 12px | 12px |
| Media ratio | 16/10 | **none (intrinsic)** | 16/10 | `auto`, 9rem col | 9rem fixed | 9rem fixed |
| Title size | 17.6px | 16px | 16px | 16px | 17.6px | 17.6px |
| Title weight | 600 | 600 | 600 | 600 | 600 | 600 |
| Title clamp | **none** | **none** | **none** | **none** | 1 (ellipsis) | 1 (ellipsis) |
| Byline | ✅ owner+rating | ✅ owner+rating | ❌ bare `OwnerBadge` | ❌ bare `OwnerBadge` | ❌ dispersed | ❌ dispersed |
| Foot | ✅ 16px pad-top | **❌ absent** | **❌ absent** | **❌ absent** | ✅ 16px | ✅ 16px |

**Does the family read as one card at different aspect ratios? Partly — better than expected.**
Padding (24px) and internal gap (12px) are genuinely uniform across all six; that spine is sound and
should be left alone. Three things break the illusion:

1. **The byline is not a family member — it is a service/product feature.** Articles get a bare
   `OwnerBadge` with no rating slot; banners scatter identity across `__id`, `__craft`,
   `RatingTracks` and `__langs`. Only 2 of 6 modifiers use the `__byline` contract.
2. **The foot is present on 3 of 6.** Product and article have no `.ex-card__foot`, so
   `margin-block-start: auto` never fires and their bodies do not bottom-align with a service card
   in the same row.
3. **Two title sizes with no stated rule.** 17.6px for service/banner, 16px for product/article via
   `--sm`. Defensible (a masonry product tile is smaller) but currently undocumented and applied by
   habit.

## 4. Separation-device budget

| Card | At rest | On hover | Minimal sufficient | Action |
|---|---|---|---|---|
| all `.ex-card` | tint + border + radius = **3** | + shadow = **4** | tint + radius | **drop the 1px border** |
| all `.lp-card` | tint + border + radius = **3** | + shadow = **4** | tint + radius | drop border (or delete block, §2) |
| `.cat-card` | tint + radius = 2 | + shadow = 3 | tint + radius | ✅ fine — **this is the correct budget** |
| `.fx-card` / `.subm-card` | radius only = 1 | + tint | ✅ | none |
| `.ex-projrow` | 1 hairline | + tint | ✅ | none |
| `.wsp-mcard` | tint (+ inset ring on self/invited) | tint change | ✅ ring is state, not decoration | none |

**Flagged for border AND shadow AND tint simultaneously:** every `.ex-card` and every `.lp-card` on
hover — 12 of the 20 census entries. `.cat-card` proves the border is unnecessary: it separates
cleanly from the console with `--surface-1` + radius alone.

The house rule permits a border here (the card is interactive via the stretched link), but §B.4 says
it must be *justified*. On a `--surface-2` card against a `--surface` page the tonal step already
does the work; the border is doing nothing the tint isn't, and it forces a second hover channel
(`border-color`) that competes with the shadow.

## 7. The overlay chip system — **measured contrast**

Are they one visual language? **Within explore, yes. Across the codebase, no — three chip languages.**

| Chip | Radius | Size | Weight | Padding | Background |
|---|---|---|---|---|---|
| `.ex-promoted` | `--radius-xl` | 0.66rem | 600 | `sp1 sp2` | `--ex-chip-on-media` (**solid**) |
| `.ex-media__type` | `--radius-xl` | 0.68rem | 600 | `sp1 sp2` | solid |
| `.ex-media__price` | `--radius-xl` | 0.95rem | **300** | `sp1 sp3` | solid |
| `.ex-media__tag` | — (`ui-tag`) | — | — | — | — |
| `.lp-product__price` | `--radius-xl` | 0.85rem | **600** | `sp1 sp3` | **`--lp-glass` 60% + blur** |
| `.cat-card__status` | **`--radius-sm`** | 0.68rem | **700** | `px sp2` | **70% + blur** |
| `.cat-card__flag--promo` | `--radius-sm` | 0.66rem | 700 | `px sp2` | tint mix |

Explore's three are coherent (same radius, same weight family, ±0.02rem size) except the price chip's
deliberate thin 300 weight, which matches the uniform pricing treatment — justified. Catalogue uses a
different radius (`--radius-sm` vs `--radius-xl`) and a heavier weight (700 vs 600).

**Legibility over an arbitrary user-uploaded image — computed with the live tokens:**

| Chip | Dark theme | Light theme | Verdict |
|---|---|---|---|
| `.ex-*` solid, `--on-surface` ink | **14.37:1** | **17.14:1** | ✅ pass |
| `.ex-media__type` Session (`--primary`) | **10.87:1** | **5.38:1** | ✅ pass |
| `.ex-media__type` Direct Deliverable (`--secondary`) | **10.88:1** | **6.43:1** | ✅ pass |
| `.lp-product__price` on a light photo | **3.75:1** | 17.14:1 | ❌ **fails AA in dark** |
| `.cat-card__status` success tone, light cover | **4.07:1** | 6.47:1 | ❌ **fails AA in dark** |
| `.cat-card__status` warning tone, dark cover | 11.4:1 | **3.05:1** | ❌ **fails AA in light** |

**This is the single clearest finding in the audit.** The explore side already solved this — the
comment at `explore.css:21-38` documents the exact measurements, concludes "an image-backed chip is
not glass — it is a label, and it gets the solid surface", and sets `--ex-chip-on-media:
var(--surface)`. **That fix was never propagated.** Marketing and catalogue still run the construction
it replaced, and both fail AA at their worst case.

**Collisions.** `.ex-flags` sets `max-inline-size: calc(100% - 2 * var(--space-3))`
(`explore.css:678`) — it reserves no room for the top-right `.ex-actions` cluster (2 × 2rem + gap ≈
4.5rem). At 246px card width with the longest label ("Direct Deliverable") the stack ends 47px clear,
so it does not collide today, but nothing prevents it. `.cat-card__flags` solves this explicitly with
`inset-inline-end: 2.6rem; /* clear the top-right kebab */` (`catalogue.css:737`). Explore should
adopt the same reservation.

## 8. Type & truncation — measured stress test

Applied to a live `.ex-card--service` (246px wide) on `/view`: a 103-character title, a
36-character handle, and the price `£12,000 – £48,000`.

| Slot | Rule | Result |
|---|---|---|
| `.ex-card__title` | **none** — no clamp, `overflow: visible` | 26px → **132px** (1 → 5 lines) |
| Card height | — | 368px → **447px (+79px)** |
| **Sibling card height** | equal-height row | **also 447px** — one long title inflates every card in the row |
| `.ex-card__foot` | `flex-wrap: nowrap`, no min-width | `scrollWidth 208 > clientWidth 196` — **12px overflow** |
| `.ex-price` | no truncation | does not itself overflow; it pushes `.ex-muted` out |
| `.ex-owner__handle` | `.ex-owner__nametext` has ellipsis; handle does not | long handle rides the flex shrink, no explicit clamp |
| `.ex-banner__nametext` | ✅ ellipsis + nowrap | correct |
| `.ex-talent__headline` | ✅ ellipsis + nowrap | correct |
| `.ex-projrow__desc` | ✅ `line-clamp: 2` | correct |
| `.cat-card__title` | `-webkit-line-clamp: 2` — **missing the standard `line-clamp`** | works in WebKit/Blink, unclamped elsewhere |

So the *only* unclamped title in the whole system is `.ex-card__title` — the one used by four of six

**Two focus languages coexist.** `--focus-ring-shadow` — the generated two-tone halo+ink composite
from `theme-engine.ts:155` — is used **218 times** across the codebase and is canonical precisely
because no single colour clears 3:1 against both the control fill and the page. The legacy
`outline: 2px solid var(--primary)` survives at **46 sites**, and every card in the explore and
marketing families is one of them (`explore.css:564`, `landing.css:583`).

`:visited` is unstyled everywhere. For a discovery feed the user scans repeatedly, that is a real
missed affordance, though styling it on a stretched link is constrained by privacy rules — worth a
deliberate decision rather than an omission.

Hover treatment is inconsistent by accident: **three lift distances** (−2 / −4 / −6px) and **three
zoom scales** (1.04 / 1.045 / 1.05) across four card families, with no rule distinguishing them.
